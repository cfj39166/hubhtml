# 社区 · 邻里服务

**一句话定位**：面向 100 栋超大型小区的"低偿邻里互助"平台。微信小程序作为居民与服务者的统一入口（不做独立 App），Web 管理后台供平台运营，楼栋协调人作为 100 栋楼分布运营的本地支点。

## 核心设计原则

1. **先核验，再开放**：住户核验注册，确认"真实邻居"才开放服务。
2. **风险分级（A/B/C 三类）**：低风险互助、中风险上门服务、机构服务分区运营，准入门槛与协议各不相同。
3. **楼栋为运营单元**：匹配半径按"同楼栋 → 同片区 → 全小区"逐级扩大，楼栋协调人做本地支点，楼栋开通开关保证供给先行。
4. **信任可视化 + 证据链自证**：三层信任标识（真实邻居/平台认可/社区信赖）让信任可判断；订单凭证、协议签署、聊天留痕形成证据链，平台以居间方身份自保。
5. **低偿而非免费**：市场化定价失去邻里意义，免费制造人情债，低偿 + 平台低抽成最可持续。
6. **双向约束**：需求方与服务者同受信用分约束，保护供给端意愿。

## 快速体验（交互原型 v1）

**方式一**：直接双击打开 `index.html`（Chrome/Edge 下四端数据互通）。
**方式二**（推荐）：在项目目录运行 `python -m http.server 8765`，然后访问 [http://127.0.0.1:8765/index.html](http://127.0.0.1:8765/index.html)。

| 页面 | 入口 | 演示内容 |
|---|---|---|
| [index.html](index.html) | 平台总览 | 设计原则、四端入口、P0闭环清单、演示路径引导 |
| [resident.html](resident.html) | 居民端 | 场景化发布、B类协议签署、红线拦截、支付分账、验收评价、信用中心、隐私授权 |
| [provider.html](provider.html) | 服务者端 | 三层认证、资质到期提醒、可接品类开关、接单大厅、留痕拍照、收入结算、差评申诉 |
| [coordinator.html](coordinator.html) | 楼栋协调人端 | 本楼需求初审、异常标记、服务者推荐、纠纷初调、楼栋看板 |
| [admin.html](admin.html) | 管理后台 | 审核队列、风险预警池、纠纷工单池、品类/协议/信用配置、供需热力图、楼栋开通开关、审计日志 |

数据存于浏览器 localStorage，四端联动：**居民发单 → 服务者接单 → 协调人初调 → 后台判定**全程闭环。后台「系统设置」可一键重置演示数据、导出 JSON。

## 第一版最小闭环（P0 组合）

1. 住户核验注册
2. 场景化首页 + A类服务发布
3. 同楼栋/同片区匹配
4. 三层信任标识
5. 订单凭证拍照 + 时间戳
6. B类协议强制签署
7. 低偿线上支付 + 即时结算
8. 双向评价 + 投诉
9. 服务者分层认证 + 资质到期提醒
10. 楼栋协调人 + 楼栋开通开关
11. 风险订单预警 + 纠纷工单
12. 高风险红线拦截 + C类机构入口占位

**第一版明确不做**：邻里社交动态、积分商城、排行榜、复杂AI匹配、独立App、全小区统一大池子。理由：供给密度和信任基础不足时，这些功能只会增加噪音，不会增加闭环。
